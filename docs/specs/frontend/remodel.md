# Remodel: play with your house (spec, frontend + backend, Vellum)

Status: draft, 2026-11-14, by Beatrice (bbeatricecretu). Branch `feature/peer-to-peer`. Builds on the project chat
(`chat.md`, `frontend/src/engineer/ProjectChat.tsx`). Nothing here is built yet.

## Purpose

Inside the existing project chat, a new mode called **"Remodel: play with your house"** lets the user change their
house and see the result as a new 2D floor plan generated by the AI. It is for playing with ideas ("what if the
kitchen were open to the living room?"), not for producing construction drawings.

It works **only on a house plan**: a project whose drawings include at least one floor plan of a house. On any other
project (sections only, technical sheets, non-residential buildings) the Remodel button is hidden or disabled with
the line "Remodel works on house floor plans only."

## Where it lives

- In the chat bar of `ProjectChat`, next to the ask box: a **Remodel** button.
- Clicking it switches the chat into Remodel mode for the current house plan: the current 2D plan appears in the
  thread as the starting point, and the chat bar shows the three ways to remodel described below.
- Each AI reply in Remodel mode is a turn in the same thread: a short text explaining what changed, plus the new 2D
  plan image. Every new turn starts from the latest plan, so changes stack ("now also move the bathroom door").
- Each plan turn has "Undo" (go back to the previous plan) and "Show original".

## The three options

### 1. Write what you want to change

- The user types a request in the chat bar, e.g. "Make the bedroom 1 m wider", "Add a window in the kitchen facing
  south", "Join the kitchen and the living room into one open space".
- The AI regenerates the house plan in 2D with the change applied and replies with the new plan and a short list of
  what changed (rooms moved, walls removed or added, new areas).
- If the request cannot be done (e.g. it would remove a load-bearing wall, or makes no sense on this plan), the AI
  says so in plain words and suggests the nearest thing it can do.

### 2. Draw or circle on the plan

- The user can draw directly on the current 2D plan: circle an area, draw a line where a new wall should go, cross
  out a wall to remove it, sketch a rough room shape.
- Tools on the plan: pen (free drawing), circle/ellipse, eraser, clear. One colour is enough.
- The user can add a short text with the drawing ("make this bigger", "put a door here"), but the drawing alone is
  also allowed.
- The drawing is sent to the AI together with the plan; the AI replies with the modified 2D plan, following what was
  drawn.

### 3. Drag and drop elements

- In the chat bar, a button (e.g. a "+" or "Elements" icon) opens a panel of house elements the user can pick:
  furniture and fixtures such as bed, sofa, dining table, desk, wardrobe, bathtub, shower, toilet, sink, kitchen
  counter, fridge, washing machine, sauna stove.
- The user can drag an element:
  - **onto the plan**, to place it at a chosen spot; the AI checks the spot and returns the plan with the element
    drawn in (and says if it does not fit, e.g. blocks a door or is too big for the room);
  - **into the prompt**, as a chip in the chat bar, and ask "where does this fit best?". The AI picks the best place
    (or a few options) and returns the plan with the element(s) placed and a sentence on why.
- Several elements can be dragged at once ("where do a double bed and a wardrobe fit best?").

## What the AI must respect

- Keep the parts of the house the user did not ask to change exactly as they were.
- Keep the plan readable as a 2D floor plan: walls, doors, windows, room names and areas.
- Use real sizes (elements at their real-world size, rooms in m²), using the plan's scale.
- Never present the result as a checked or buildable design: every generated plan carries the label
  "AI concept, not a construction drawing".

## Out of scope (for now)

- 3D views.
- Editing elevations, sections or technical sheets.
- Saving remodels as new drawings in the project or exporting them (maybe later: "Download plan" as PNG).
- Building-code checks of the remodelled plan.

## Open questions

- Which model generates the plan: an image model editing the plan picture, or a model that edits a structured plan
  (rooms and walls as data) that we then render? The second keeps sizes right; the first is faster to build.
- Do we need a backend endpoint per option, or one `POST /api/projects/{id}/remodel` taking
  `{text?, drawing?, elements?, base_plan}`? Needs a decision record in `docs/decisions/` and a board `decision`
  thread before frontend and backend code against it.
- How do we tell that a project is a house plan: the triage class of its drawings, or the user picks the floor plan?
